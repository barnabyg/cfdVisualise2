# Issue tracker

Publish tickets and specs as GitHub issues in `barnabyg/cfdVisualise2`.
When a skill requests a ticket, read the issue body, labels, and comments.

Prefer the connected GitHub app for supported operations. When using `gh`,
target `--repo barnabyg/cfdVisualise2` explicitly and use `--body-file`
for multiline text.

Link child tickets using GitHub sub-issues and track blockers using native
issue dependencies. If those features are unavailable, put `Part of #<parent>`
or `Blocked by: #<blocker>` at the top of the child issue body. A ticket is
unblocked when all its blockers are closed.

When closing an issue with an explanation, post the comment before closing it.

PRs as a request surface: no.
