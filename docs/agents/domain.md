# Domain docs

Before exploring an area, read the root `GLOSSARY.md` and any relevant
architecture decision records in `docs/adr/`. If either is absent, proceed.

Use glossary terms consistently in issues, proposals, code, and tests.
When a concept needs a name, consult the domain-modeling skill. Create
glossary entries and decision records as terms and decisions are agreed.

If a proposal conflicts with an existing decision record, cite the record
and explain why the decision warrants reconsideration.
